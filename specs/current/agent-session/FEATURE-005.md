# History synchronization

## R1 - Source and policy

Use xhluca/session-migrate as the source reference for neutral events, readers, writers, validation, loss accounting and test approach. Pin the reviewed upstream revision. Preserve its MIT copyright and license in copied or adapted substantial code; identify provenance and modifications. Do not copy proprietary harness code. No LLM inference or background Keeper. History is opt-in: explicit `sync` enables history for that target by creating history/index.json; config-generated shutdown hooks call sync only for enabled targets, or if user opts in through the managed integration. Document how to enable it. Native transcripts remain untouched. Warn before cross-provider transfer; users must understand that a resumed cloud harness can submit historical content to its provider. No automatic redaction promise.

## R2 - Storage

Use history/ beside agent.json. UTF-8 JSONL, LF, deterministic JSON serialization, one complete event per line. Use daily UTC rotation and maximum segment size 256 KiB by default. Environment `AGENT_SESSION_HISTORY_MAX_SIZE` default `256K`; K/M mean powers of 1024, positive integer bytes also accepted. Use filenames YYYY-MM-DD.NNN.jsonl, ordered lexically by date and numeric sequence (pad to at least 3 digits; sort sequence numerically). Date is UTC publication date, not untrusted event timestamp. Rotate before appending an event that exceeds limit or when date changes. Never split event; an oversized event can occupy a larger file. No compression, pruning or automatic deletion. Retain all portable records. Append only; closed segments immutable. Handle clock rollback without reordering history (use index ordering or reject unsafe rotation). Git friendly, no automatic commit. Smaller segments do not limit total Git size or model context.

## R3 - Portable event model

Adopt the upstream validated event model where practical; define and document a versioned serialization mapping before implementation. At minimum preserve ordered user/assistant text, linked completed tool calls and results, supported images and compatible compaction summaries. Each record has stable canonical event identity and source provenance (harness, native session, native event identity or validated cursor). Preserve repeated identical text as separate events. Do not migrate private/signed reasoning, auth stores, pending approvals, shell state, caches or runtime configuration. Record omitted/transformed event counts and reasons without content. Preserve source files for unsupported content. Do not claim lossless migration.

## R4 - Index and transaction

index.json contains version, canonical revision, active source harness/session, per-session imported boundary and validated native cursor, segment publication metadata if necessary, and content-free loss counters. A checkpoint binds to exact native session identity, not merely harness or event count. Track canonical-to-native projection boundary, including omitted events; a re-export of imported content is not new history. Use durable staged writes under one target/history lock; publish index only after data is durable. Recovery must detect uncommitted tails, incomplete records and incomplete native imports without duplicating events or clobbering source. Never guess based on timestamps or text equality. If cursor validation fails due to rewind, branch, compaction or transcript replacement, stop with conflict unless adapter can prove continuity. Keep one authoritative writer for the logical history.

## R5 - Direction and run

`sync` with no harness checkpoints current/last native session into history. `sync --harness H` first checkpoints authoritative source, then materializes latest history for H if necessary. If same session is up to date, no-op. If target native session is older, create a new native session; do not rewrite existing native transcript/database. If native history is missing and a valid canonical copy exists, materialize a new session with explicit result. If no history exists, report no history; do not invent content. If independently extended histories diverge, fail with conflict. Do not materialize into an active session or switch while another writer is active. Explicit --session identifies the requested native session; reject unrelated history unless deliberately initialized as the first source. --dry-run makes no changes. JSON result includes direction, source/target harness and ID, revision, added count, omission counters and warnings. Update destination mapping only after verified import; do not change current harness until init confirms launch. Repeated sync without changes must reuse the already verified materialization. `run` does final sync before a switch when history enabled, including recovery after failed shutdown; never silently start fresh or discard context. Without history enabled, resume each harness independently. Shutdown sync is best effort; always attempt stop within hook budget. Do not use timestamps alone for direction.

## R6 - Verification

Test all 12 ordered cross-harness routes with native fixtures, repeated switches, identical messages, large records, rotation, compaction and interrupted publication. Compare portable content, linked tool IDs and loss counters. A native resume oracle must prove the receiving client loads imported context and adds a turn. Use isolated mock model endpoint where possible. Do not promise full context restoration or unchanged token costs.
## R7 - Source ownership

The shared history.py owns the portable event model, JSONL storage, rotation, index, synchronization direction, transaction recovery and conflict detection. The sync command calls these common operations. The run command uses the same operations before launch. The shared module MUST NOT parse or generate native harness formats. Each Harness implementation provides read_history and write_history. Put all adapted session-migrate native readers and writers inside the corresponding harness package. Put only harness-neutral model and validation code in the common module. Preserve applicable upstream copyright and license notices. Both native and common components exchange typed portable records and cursor results. Do not create a second native adapter registry.
