# Prepare release candidate

## Objective

Product root: `works/`. Run product commands there. Store investigations in `probes/AS-016/`.

Finalize documentation, compatibility table, licenses, build and install tests. Prepare publication instructions.

## Acceptance criteria

- [ ] All release gates pass or blockers explicitly reported.
- [ ] Wheel includes executable plugins/extensions and license notices. No JSON hook templates.
- [ ] PyPI name checked; clean install verified.
- [ ] No publish until explicit owner approval.

- [ ] Verify that all harness-local integration resources are included in the wheel and can be installed from it.

- [ ] Verify documented defaults and environment variables match the installed CLI and tests.

- [ ] CI passes on the required Linux/macOS Python matrix. Required Linux native acceptance gates pass. Record macOS native compatibility evidence and any limitations.
- [ ] Verify requirement-to-test map and at least 85% branch coverage. Verify wheel and sdist clean-install smoke tests.
- [ ] Verify release workflow build-only dry run and artifact handoff. Verify OIDC permission separation and owner approval gate without publishing.
- [ ] Give the owner the exact repository and workflow values for PyPI Trusted Publishing. List manual actions. Do not create a release tag or publish.

## Execution

Record commit, test commands, results and limitations.

## Review

Record independent findings and acceptance or rejection.
