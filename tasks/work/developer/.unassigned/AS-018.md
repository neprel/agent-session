# Implement GitHub CI and release workflows

## Objective

Create CI and release workflows as specified in FEATURE-011 R8-R9. Add the owner publishing guide to product documentation.

## Acceptance criteria

- [ ] CI runs locked tests on Linux and macOS with the specified Python matrix, lint, coverage and package smoke tests.
- [ ] Native CI provisions pinned clients and runs the required isolated mock-provider tests with no real credentials.
- [ ] CI reports failures and unexpected skips. No real transcript or secret artifacts.
- [ ] Release verifies tag, commit, test gates and distribution contents. Build-only manual run cannot publish.
- [ ] Separate publish job uses pypi environment, owner approval, job-level OIDC and exact tested artifacts. No long-lived PyPI token.
- [ ] Pin action SHAs and uv version. Test workflow syntax and build-only path. Do not create a release tag or publish.

## Execution

Record commit, test commands, results and limitations.
